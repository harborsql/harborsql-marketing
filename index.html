Where it fits

A targeted endpoint alternative for supported read-only workloads.

HarborSQL is strongest when an application already speaks the Databricks SQL connector protocol, the data is in Unity Catalog Delta, and a full SQL Warehouse is more infrastructure than the workload needs.

Change the endpoint URL

Keep the Databricks SQL connector in your app and route supported queries to HarborSQL instead of a warehouse endpoint.

Keep Unity Catalog in charge

HarborSQL checks access through Unity Catalog and uses short-lived table credentials for the caller.

Serve reads near the data

Run the open-source server on your own compute, colocated with the data and scaled for the serving path you actually need.

Benchmark before switching

It is not a full warehouse clone. Start with read-only SELECT workloads and measure your queries against the current support matrix.

How it works

Keep the client shape. Move execution onto your compute.

HarborSQL accepts Databricks SQL connector-style requests, resolves Unity Catalog Delta tables as the caller, opens the data with delta-rs, executes read-only SQL with DataFusion, and returns Databricks-compatible result sets.

Security model

Authorization stays where your governance already lives.

Unity Catalog remains the authority

HarborSQL forwards the caller bearer token to Unity Catalog and asks for temporary table credentials only for tables the caller can access.

No persistent token storage

Databricks bearer tokens and temporary cloud credentials are not persisted. Cached table providers are keyed by a process-local HMAC of the caller token.

Read-only by design

The current server targets read-only SELECT workloads, result limits, session limits, operation TTLs, and request body limits.

Private by default

The local server binds to 127.0.0.1 by default. Upstream Databricks hosts use HTTPS unless explicitly overridden for local test doubles.

Client compatibility

From warehouse endpoint to HarborSQL endpoint.

Existing Python clients keep the Databricks SQL connector. When HarborSQL is behind HTTPS, the common migration path is changing the server hostname to the HarborSQL endpoint.

Before Connect directly to a SQL warehouse 
from databricks import sql
import os

connection = sql.connect(
    server_hostname="<workspace-host>",
    http_path="/sql/1.0/warehouses/abc123",
    access_token=os.environ["DATABRICKS_TOKEN"],
    catalog="workspace",
    schema="analytics",
)

with connection.cursor() as cursor:
    cursor.execute("SELECT count(*) FROM events")
    print(cursor.fetchone())
After Run HarborSQL behind HTTPS and change the host 
export HARBORSQL_DATABRICKS_HOST="https://<workspace-host>"

harborsql server

Local server

Run it on your laptop or ship it beside your workload.

Release publishing produces a Linux x86_64 Docker image, Linux binary archive, and macOS Apple Silicon archive when enabled. The same server path works for local development, EC2 benchmarks, and private deployments behind TLS.
