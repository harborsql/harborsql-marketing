Benchmarks

ClickBench: 121.6s HarborSQL vs 170.3s Databricks.

The latest HarborSQL v0.1.2 ClickBench run used the Docker image on an EC2 i3.2xlarge instance against the optimized table. The Databricks baseline used a 2X-Small SQL Warehouse against the same benchmark shape. The point is not that every data-platform workload should leave Spark; it is that many SQL requests fit in memory and should not pay for distributed compute.

Cost profile

Up to 8x lower compute cost when Spark is more than the query needs.

Using client wall time, the benchmark Databricks rate is $3.60/hour for a 2X-Small SQL Warehouse. The HarborSQL dashboard assumption is $0.724/hour for an i3.2xlarge in eu-west-3; the regional cost analysis also records $0.624/hour for us-west-2.

On the current run that is $0.1703 for Databricks versus $0.0245 for HarborSQL under the eu-west-3 assumption: 6.96x lower, or 85.6% less compute cost. At the lower recorded on-demand i3.2xlarge rate, the same run is 8.08x lower, or 87.6% less compute cost.

Positioning

An in-memory SQL path for Unity Catalog Delta reads.

HarborSQL does not try to reproduce every Databricks SQL Warehouse feature. It focuses on the many read-only requests that are not big-data jobs: queries that fit in memory, still need Unity Catalog authorization, and should not require a Spark-backed warehouse to answer.

Offload small reads

Small

Route memory-sized SELECT workloads to HarborSQL instead of Spark compute.

Keep governance

UC

Keep Unity Catalog as the authority for Delta table access and credentials.

Keep Spark where it belongs

Spark

Use Databricks compute for large distributed jobs, writes, and unsupported SQL.
